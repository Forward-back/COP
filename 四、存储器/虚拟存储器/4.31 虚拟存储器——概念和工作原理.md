# 4.31 虚拟存储器——概念和工作原理

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.31）｜重要度 ★★★★★｜常见考法：选择题/大题（虚拟地址、MMU、页表、TLB、Cache 与虚存区别）

**一句话核心**：虚拟存储器把主存和辅存组织成一个“逻辑上连续、容量更大”的地址空间；CPU 用虚拟地址，MMU 用页表把它翻译成物理地址

## 一、为什么需要虚拟存储器

**容量问题**
- 程序规模可能超过物理主存容量
- 虚拟存储器把暂时不用的页放到辅存，需要时再调入主存

**地址空间问题**
- 多道程序需要各自的地址空间，互相隔离
- 虚拟地址空间可以大于物理地址空间
- 每个进程有独立的页表，实现隔离与保护

**编程与装载问题**
- 程序员不必关心物理内存布局
- 程序按虚拟地址编写，由 MMU 完成地址转换

**易错**
- 虚拟存储器不是“物理内存变大”，而是“用辅存扩展逻辑地址空间”
- 虚拟地址空间可以大于物理地址空间，但物理内存仍是实际容量
- 虚拟存储器由 OS 与硬件（MMU）共同管理，不是纯软件

## 二、页式虚拟存储器的基本思想

**分页**
- 虚拟地址空间分成固定大小的页（虚拟页）
- 物理地址空间分成同样大小的页框（物理页）
- 页大小相同，页内偏移相同

**地址转换**
- 虚拟地址 = 虚拟页号 VPN + 页内偏移 Offset
- 物理地址 = 物理页号 PPN + 页内偏移 Offset
- 页表记录 VPN → PPN 的映射
- 页表项还包含有效位、脏位、访问权限等

**缺页**
- 访问的虚拟页不在主存 → 缺页异常
- OS 从辅存调入该页，更新页表，重新执行指令

**易错**
- 页内偏移在转换前后不变
- 页表在主存中，不是 Cache
- 缺页是异常，不是中断；处理完要重新执行指令

## 三、虚拟存储器与 Cache 的区别

| 维度 | Cache | 虚拟存储器 |
| --- | --- | --- |
| 目的 | 缓解 CPU 与主存速度差 | 扩展地址空间、容量管理 |
| 数据单位 | 块（block） | 页（page） |
| 管理者 | 硬件自动 | OS + MMU 硬件 |
| 地址 | 物理地址/主存地址 | 虚拟地址 → 物理地址 |
| 缺失代价 | 访问主存 | 访问辅存（缺页） |
| 对程序员 | 透明 | 基本透明，由 OS 管理；地址空间可见 |

**易错**
- Cache 与虚存都利用局部性，但层次不同
- Cache 缺失由硬件处理；缺页由 OS 处理
- 虚拟存储器不是“Cache 的扩大版”；它解决的是容量/地址空间问题
