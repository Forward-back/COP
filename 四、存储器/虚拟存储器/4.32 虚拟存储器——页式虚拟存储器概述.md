# 4.32 虚拟存储器——页式虚拟存储器概述

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.32）｜重要度 ★★★★★｜常见考法：选择题/大题（虚拟页/物理页、页大小、请求分页、页表、Cache/主存/辅存层次）

**一句话核心**：页式虚存把虚拟地址空间和物理地址空间都切成同样大小的页，用页表记录虚拟页到物理页的映射，按需调入

## 一、虚拟存储器分类

![](../../images/Pasted%20image%2020260923171126.png)

**提炼**
- 页式：按固定大小分页，页内偏移不变；最常用
- 段式：按逻辑段划分，段长可变；便于保护和共享
- 段页式：先分段，段内再分页；兼顾逻辑与物理管理

**易错**
- 页式虚存的页大小固定，段式段长可变
- 408 计组主要考页式，段式/段页式了解概念

## 二、概述

### 2.1 虚拟页和物理页

![](../../images/Pasted%20image%2020260923171247.png)

**提炼**
- 虚拟地址空间分成虚拟页（VP），物理地址空间分成物理页（PP）
- 虚拟页和物理页大小相同，页内偏移位数相同
- 虚拟页号 VPN 的位数大于物理页号 PPN 的位数
- 页表项记录 VPN → PPN 的映射

**公式**

$$\text{虚拟地址}=\text{VPN}\mid\text{Offset}$$

$$\text{物理地址}=\text{PPN}\mid\text{Offset}$$

$$\text{页大小}=2^{\text{Offset 位数}}$$

**易错**
- 虚拟页号位数 > 物理页号位数，所以虚拟地址空间更大
- Offset 位数由页大小决定，转换前后不变
- 页是逻辑单位，页框（物理页）是物理单位

### 2.2 请求分页

![](../../images/Pasted%20image%2020260923171324.png)

**提炼**
- 程序运行时不需要把所有页都装入主存
- 只装入当前需要的页，其余留在辅存
- 访问未装入的页 → 缺页异常 → OS 调入
- 页表项的有效位表示该页是否在主存

**易错**
- 请求分页是“按需调入”，不是“一次性全部装入”
- 缺页由硬件触发异常，OS 处理
- 有效位为 0 不一定是“页不存在”，可能是“不在主存”

### 2.3 Cache、主存、辅存结构

![](../../images/Pasted%20image%2020260923171426.png)

**层次**
- Cache：缓存主存中的活跃数据，硬件管理
- 主存：存放当前运行的页
- 辅存：存放未装入主存的页（磁盘、SSD）
- 页表：记录虚拟页到物理页的映射，通常在主存

**提炼**
- 虚存层次是“主存—辅存”，Cache 层次是“Cache—主存”
- 两级层次可以同时存在：CPU → TLB → Cache → 主存 → 辅存
- 缺页代价远大于 Cache 缺失

**易错**
- 页表不是 Cache；页表在主存，TLB 才是页表的 Cache
- 虚存缺失（缺页）由 OS 处理；Cache 缺失由硬件处理
- 主存—辅存层次对程序员可见，Cache—主存层次透明

## 三、总结

![](../../images/Pasted%20image%2020260923171450.png)

| 概念 | 含义 | 关键点 |
| --- | --- | --- |
| 虚拟页 VP | 虚拟地址空间的固定大小页 | VPN 位数多 |
| 物理页 PP | 主存的固定大小页框 | PPN 位数少 |
| 页表 | VPN → PPN 的映射表 | 在主存 |
| 有效位 | 页是否在主存 | 缺页判断 |
| 缺页 | 访问的页不在主存 | OS 调入 |
| 页大小 | 页的字节数 | $2^{\text{Offset}}$ |

**易错**
- 虚拟地址空间 > 物理地址空间，但页大小相同
- 页表项不仅存 PPN，还有有效位、脏位、权限位
- 缺页处理后要重新执行触发缺页的指令
