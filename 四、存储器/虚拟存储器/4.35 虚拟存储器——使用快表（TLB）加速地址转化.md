# 4.35 虚拟存储器——使用快表（TLB）加速地址转化

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.35）｜重要度 ★★★★★｜常见考法：大题（TLB 地址划分、全相联/组相联、TLB 命中/缺失、与页表关系）

**一句话核心**：TLB 是页表项的 Cache；TLB 命中直接得 PPN，TLB 缺失才查页表；Offset 始终不变

## 一、TLB概述

![](../../images/Pasted%20image%2020260923201050.png)

**提炼**
- TLB = Translation Lookaside Buffer，快表
- 专门缓存“经常访问的页表项”，不是缓存数据
- 容量小、速度快，通常采用全相联或组相联
- TLB 缺失时采用随机替换或近似 LRU

**易错**
- TLB 不是页表，也不是数据 Cache
- TLB 缓存的是 PTE（虚拟页号 → 物理页号 + 权限）
- TLB 命中只说明页表项在 TLB，不说明数据在 Cache

## 二、全相联和组相联方式下的虚拟地址划分

![](../../images/Pasted%20image%2020260923201202.png)

### 2.1 全相联方式的举例

![](../../images/Pasted%20image%2020260923201329.png)

**地址划分**
- 全相联 TLB：虚拟地址 = 虚拟页号 + 页内偏移
- 虚拟页号整体作为 Tag，与 TLB 中所有表项并行比较
- 没有 TLB 索引

**查找**
1. 用虚拟页号与所有 TLB 表项的 Tag 比较
2. 命中 → 取出 PPN
3. 缺失 → 查页表，更新 TLB

**易错**
- TLB 的 Tag 是虚拟页号（或其一部分），不是物理页号
- 全相联 TLB 需要比较所有表项
- TLB 命中后仍要检查权限位

### 2.2 组相联方式的举例

![](../../images/Pasted%20image%2020260923201446.png)

**地址划分**
- 虚拟页号分成 TLB 标记（Tag）和 TLB 索引（Index）
- 页内偏移不变
- 用索引定位组，再在组内比较 Tag

**查找**
1. 用 TLB 索引定位组
2. 组内并行比较 Tag
3. 命中 → 取 PPN
4. 缺失 → 查页表

**易错**
- TLB 索引来自虚拟页号，不是物理页号
- 组内比较的是 Tag，不是完整虚拟地址
- TLB 索引位数由 TLB 组数决定

## 三、基于TLB的访问过程

![](../../images/Pasted%20image%2020260923201719.png)

**步骤**
1. CPU 给出虚拟地址
2. 拆分 VPN 和 Offset
3. 查 TLB：命中 → 得 PPN，转步骤 6
4. TLB 缺失 → 查页表（可能访问主存/Cache）
5. 页表项有效 → 取 PPN，更新 TLB；无效 → 缺页
6. 物理地址 = PPN + Offset
7. 访问 Cache/主存

**易错**
- TLB 命中 → 页一定在主存（PTE 有效才会装入 TLB）
- TLB 缺失 ≠ 缺页；可能只是 TLB 没缓存，页表中有有效项
- TLB 命中 ≠ Cache 命中；数据仍可能在 Cache 中缺失
- 缺页时不仅要更新页表，还要更新 TLB
