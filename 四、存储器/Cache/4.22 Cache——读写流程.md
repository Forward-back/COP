# 4.22 Cache——读写流程

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.22）｜重要度 ★★★★★｜常见考法：选择题/大题（读流程、写回/写穿、写分配/非写分配、脏位）

**一句话核心**：读操作先查 Cache，命中直接取，缺失调块；写操作分“写命中”和“写缺失”，分别选择写回/写穿、写分配/非写分配

## 一、读流程

**读操作涉及的问题**

![](../../images/Pasted%20image%2020260919193346.png)

**读操作流程图**

![](../../images/Pasted%20image%2020260919193418.png)

**步骤**
1. CPU 给出主存地址
2. 用地址中的索引找到 Cache 行
3. 比较 Tag 与有效位
4. 命中：直接读出数据
5. 缺失：从主存调入整个块，替换某行，再读出数据

**易错**
- 缺失时调入的是“块”，不是单个字
- 有效位为 0 时，即使 Tag 相同也不能算命中
- 读缺失可能触发替换算法；直接映射只能替换固定行

## 二、写流程

### 2.1 命中缓存时

**写回策略（Write-Back）**

![](../../images/Pasted%20image%2020260919193508.png)

- 写命中时只修改 Cache，不立即写主存
- 该行设置脏位（dirty bit），表示与主存不一致
- 该行被替换时，若脏位为 1，先写回主存
- 优点：减少主存写次数；缺点：控制复杂，需要脏位

**写穿策略（Write-Through）**

![](../../images/Pasted%20image%2020260919193533.png)

- 写命中时同时写 Cache 和主存
- 不需要脏位，控制简单
- 缺点：每次写都访问主存，写带宽压力大
- 常配合写缓冲（write buffer）减少等待

**易错**
- 写回不是“不写主存”，而是“延迟到替换时写”
- 写穿不是“只写主存”，Cache 也要更新
- 脏位只在写回策略中使用

### 2.2 未命中缓存时

**非写分配策略（No-Write-Allocate）**

![](../../images/Pasted%20image%2020260919193656.png)

- 写缺失时直接写主存，不把块调入 Cache
- 常与写穿配合
- 优点：避免为一次写而调入整块；缺点：后续读可能缺失

**写分配策略（Write-Allocate）**

![](../../images/Pasted%20image%2020260919193715.png)

- 写缺失时先把块调入 Cache，再在 Cache 中写
- 常与写回配合
- 优点：利用空间局部性；缺点：多一次调入

**典型组合**
- 写回 + 写分配
- 写穿 + 非写分配

**易错**
- 写分配/非写分配是“写缺失”时的策略，不是“写命中”的策略
- 写回/写穿是“写命中”时的策略
- 四种组合可以交叉，但常见组合只有两种

### 2.3 写操作流程图

![](../../images/Pasted%20image%2020260919193815.png)

**提炼**
- 先判断写命中/写缺失
- 命中：选择写回或写穿
- 缺失：选择写分配或非写分配
- 若替换的行是脏的，还要先写回主存

**易错**
- 写缺失且非写分配时，不需要读主存块
- 写缺失且写分配时，先读块再写，可能触发替换
- 脏位与有效位不是一回事：有效位表示数据是否有效，脏位表示是否与主存一致
