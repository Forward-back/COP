# 4.25B Cache——地址映射（组相联映射）

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.25B）｜重要度 ★★★★★｜常见考法：大题（组号、Tag/Index/Offset、n 路组相联、比较器数量、替换）

**一句话核心**：先按“组”直接映射，再在组内全相联；地址 = Tag + 组号 + 块内偏移

## 一、映射规则

![](../../images/Pasted%20image%2020260920181446.png)

**提炼**
- Cache 分成若干组，每组包含 $n$ 行，称为 $n$ 路组相联
- 主存块先映射到唯一一个组：组号 = 主存块号 mod 组数
- 在该组内，主存块可以放到任意一行
- 组间是直接映射，组内是全相联

**易错**
- 组号不是行号；组内还要再选行
- 组相联的“路数”指每组行数，不是总行数
- 组数 = 总行数 / 路数

## 二、信息的主存地址

![](../../images/Pasted%20image%2020260920181624.png)

**地址划分**

$$\text{主存地址}=\text{Tag}\mid\text{组号}\mid\text{Offset}$$

- Offset 位数 $=\log_2(\text{块大小})$
- 组号位数 $=\log_2(\text{组数})$
- Tag 位数 $=$ 地址位数 $-$ 组号位数 $-$ Offset 位数

**例**：32 位地址，Cache 64KB，块 16B，4 路组相联
- 总行数 $=64KB/16B=4096$
- 组数 $=4096/4=1024=2^{10}$
- Offset $=4$ 位
- 组号 $=10$ 位
- Tag $=32-10-4=18$ 位

## 三、数据的访问

![](../../images/Pasted%20image%2020260920182004.png)

**步骤**
1. 用组号找到对应组
2. 将该组内 $n$ 行的 Tag 与地址 Tag 并行比较
3. 有效位为 1 且 Tag 相等 → 命中
4. 否则缺失，从主存调入，替换组内某一行
5. 按 Offset 取字

**易错**
- 只比较目标组内的 $n$ 行，不是比较所有行
- 组内是全相联，命中可能来自任意一行
- 替换算法只在目标组内选择

## 四、硬件逻辑实现

![](../../images/Pasted%20image%2020260920182250.png)

**提炼**
- 组号译码选中一组
- 组内 $n$ 个比较器并行比较 Tag
- 命中信号选择对应行
- 未命中时，替换算法在组内选一行

**比较器数量**
- 每个组内 $n$ 个比较器
- 若各组并行工作，总比较器数为 $n \times$ 组数
- 若按“每组独立”描述，通常说“每组 n 个比较器”

## 五、总结

![](../../images/Pasted%20image%2020260920182313.png)

| 维度 | 组相联 |
| --- | --- |
| 映射规则 | 组间直接，组内全相联 |
| 地址划分 | Tag / 组号 / Offset |
| 比较器 | 每组 n 个 |
| 冲突缺失 | 比直接映射少 |
| 成本 | 介于直接与全相联之间 |
| 替换 | 组内选择 |
| 典型 | 2 路、4 路、8 路组相联 |

**公式汇总**

$$\text{组数}=\text{总行数}/\text{路数}$$

$$\text{组号}=\log_2(\text{组数})$$

$$\text{Tag}=\text{地址位数}-\text{组号}-\text{Offset}$$

**易错**
- 组号位数由组数决定，不是由行数决定
- Tag 位数比直接映射多，因为组号比行号短
- 组相联的“n 路”影响组内比较器和替换，不影响组号计算
- 全相联可看作“只有 1 组”的组相联；直接映射可看作“每组 1 行”的组相联
