# 4.25C Cache——地址映射（全相联和组相联映射习题课）

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.25C）｜重要度 ★★★★★｜常见考法：大题（三种映射对比、地址划分、比较器数量、命中判断、替换开销）

**一句话核心**：直接映射“行固定、比较器 1 个”，全相联“行任意、比较器最多”，组相联“组固定、组内任意”，是两者的折中

## 一、三种映射方式的比较

### 1.1 关联度以及开销

***关联度***

![](../../images/Pasted%20image%2020260920182456.png)

***开销***

![](../../images/Pasted%20image%2020260920182546.png)

| 维度 | 直接映射 | 全相联 | 组相联 |
| --- | --- | --- | --- |
| 映射位置 | 唯一行 | 任意行 | 唯一组，组内任意行 |
| 地址划分 | Tag / Index / Offset | Tag / Offset | Tag / 组号 / Offset |
| 比较器 | 1 个 | 每行 1 个 | 每组 n 个 |
| 冲突缺失 | 最多 | 最少 | 居中 |
| 硬件成本 | 最低 | 最高 | 居中 |
| 替换 | 无需选择 | 全局选择 | 组内选择 |
| 典型用途 | 大容量、低成本 | 小容量、高命中 | 通用折中 |

**提炼**
- 直接映射：行号 = 块号 mod 行数，硬件最简单，冲突最多
- 全相联：任意块任意行，比较器最多，冲突最少
- 组相联：组间直接、组内全相联，兼顾成本与命中率

**易错**
- 关联度越高，冲突缺失越少，但比较器和成本越高
- 直接映射不是“没有 Tag”，仍需要 Tag 区分同一行的不同块
- 全相联不是“没有组号”，而是只有一组
- 组相联的路数增加，比较器增加，组数减少

### 1.2 信息的主存地址

![](../../images/Pasted%20image%2020260920182652.png)

**地址划分对比**

| 映射 | Tag | Index/组号 | Offset |
| --- | --- | --- | --- |
| 直接 | 剩余高位 | 行号 | 块内偏移 |
| 全相联 | 剩余高位 | 无 | 块内偏移 |
| 组相联 | 剩余高位 | 组号 | 块内偏移 |

**公式**
- Offset $=\log_2$(块大小)
- 直接：Index $=\log_2$(行数)
- 组相联：组号 $=\log_2$(组数)，组数 = 行数 / 路数
- Tag = 地址位数 − Index/组号 − Offset

**易错**
- 全相联的 Tag 最长，因为没有 Index
- 组相联的 Tag 比直接映射长，因为组号比行号短
- 地址划分从低位往高位切：先 Offset，再 Index/组号，剩下是 Tag

## 二、例题

### 2.1 例题一

![](../../images/Pasted%20image%2020260920182802.png)

**考什么**：三种映射的地址划分与比较器数量
**常见错因**
- 把组相联的组号当行号
- 全相联仍去算 Index
- 比较器数量与行数/组数混淆

**解题模板**
1. 先算块大小 → Offset
2. 再算行数/组数 → Index/组号
3. 剩下为 Tag
4. 直接 1 个比较器；全相联每行 1 个；组相联每组 n 个

### 2.2 例题二

![](../../images/Pasted%20image%2020260920182833.png)

**考什么**：组相联的组号、Tag、命中判断
**常见错因**
- 组数算成行数
- 忘记组内并行比较
- 替换时选错组

**解题模板**
1. 组数 = 总行数 / 路数
2. 组号 = 块号 mod 组数
3. 组内比较所有 Tag
4. 命中取字；缺失在组内替换

### 2.3 例题三

![](../../images/Pasted%20image%2020260920182859.png)

**考什么**：关联度、比较器位数、替换开销
**常见错因**
- 比较器位数不等于 Tag 位数
- 关联度与比较器数量关系搞反
- 忘记有效位/脏位开销

**解题模板**
1. 比较器位数 = Tag 位数
2. 比较器个数 = 并行比较的路数
3. 总开销 = 数据 + Tag + 有效位 + 脏位
4. 关联度越高，比较器越多，冲突越少

**注**
- 比较器：每组中并发比较的路数
- 比较器位数：等于 Tag 位数
