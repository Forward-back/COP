# 4.25A Cache——地址映射（全相联映射）

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.25A）｜重要度 ★★★★★｜常见考法：选择题/大题（全相联地址划分、Tag 比较、比较器数量、相联存储器）

**一句话核心**：全相联允许任意主存块放到任意 Cache 行；地址只有 Tag + Offset，没有 Index，靠所有 Tag 并行比较

## 一、定义

![](../../images/Pasted%20image%2020260920180755.png)

**提炼**
- 每个主存块可以映射到任意一个 Cache 行
- Cache 行数不受主存块号限制，只受容量限制
- 命中判断需要比较所有行的 Tag
- 冲突缺失最少，但硬件成本最高

**易错**
- 全相联不是“没有映射规则”，规则是“任意行”
- 全相联没有 Index 字段
- 全相联需要替换算法，直接映射不需要选择

## 二、查找方式

### 2.1 示意图

![](../../images/Pasted%20image%2020260920180854.png)

**地址划分**

$$\text{主存地址}=\text{Tag}\mid\text{Offset}$$

- Offset 位数 $=\log_2(\text{块大小})$
- Tag 位数 $=$ 地址位数 $-$ Offset 位数
- 没有 Index 字段

### 2.2 硬件逻辑实现

![](../../images/Pasted%20image%2020260920180951.png)

**查找步骤**
1. 用 Offset 定位块内字
2. 把地址 Tag 送到所有行的比较器
3. 每个有效行并行比较 Tag
4. 任一相等 → 命中，选出对应行
5. 全部不相等 → 缺失，调入并替换某行

**易错**
- 比较器数量等于 Cache 行数
- 只有有效位为 1 的行才参与命中
- 全相联的 Tag 位数比直接映射多，因为要去掉 Index

## 三、总结

***相联存储器***

![](../../images/Pasted%20image%2020260920181020.png)

**提炼**
- 相联存储器按内容并行比较，不按地址访问
- 全相联 Cache 的 Tag 比较依赖相联存储器
- 比较器数量多，是全相联成本高的原因

***特点***

![](../../images/Pasted%20image%2020260920181100.png)

| 维度 | 全相联 |
| --- | --- |
| 映射规则 | 任意块 → 任意行 |
| 地址划分 | Tag / Offset |
| 比较器 | 每行一个，全部并行 |
| 冲突缺失 | 最少 |
| 成本 | 最高 |
| 替换 | 需要替换算法 |
| 适用 | 小容量、高命中率场景 |

**公式**

$$\text{Tag}=\text{地址位数}-\log_2(\text{块大小})$$

$$\text{Cache 总容量}=\text{行数}\times(\text{数据位}+\text{Tag 位}+\text{有效位}+\text{脏位})$$

**易错**
- 全相联的 Tag 不是“主存块号”，而是“主存地址去掉块内偏移”
- 全相联的比较器数量多，硬件成本高
- 全相联没有冲突缺失，但仍有容量缺失和 compulsory 缺失

**考什么**：全相联地址划分、Tag 比较、命中判断
**常见错因**
- 仍然去算 Index
- 比较器数量算成 1
- Tag 位数忘记减去 Offset

**解题模板**
1. Offset = $\log_2$(块大小)
2. Tag = 地址位数 − Offset
3. 所有有效行并行比较 Tag
4. 命中则按 Offset 取字，否则调入并替换
