# 4.24 Cache——地址映射（直接映射习题课）

**考纲定位**：计算机组成原理 · 第 4 章 存储器（4.24）｜重要度 ★★★★★｜常见考法：大题（地址划分、Cache 容量、Tag/Index/Offset、命中率、数组访问）

**一句话核心**：先拆地址，再算行号与 Tag，最后算容量；数组题先看访问顺序是否利用空间局部性

**图旁说明**：题图与解析图保留；文字只给“考什么 / 常见错因 / 解题模板”，不转写图中解答

## 例题一

![](../../images/Pasted%20image%2020260919201657.png)

**考什么**：直接映射的地址划分与 Cache 总容量
**常见错因**
- 把 Cache 容量直接当行数，忘记除以块大小
- Tag 位数用总地址位数减 Offset，漏减 Index
- 总容量只算数据，忘记 Tag/有效位/脏位

**解题模板**
1. 行数 = Cache 数据容量 / 块大小
2. Offset = $\log_2$(块大小)
3. Index = $\log_2$(行数)
4. Tag = 地址位数 − Index − Offset
5. 总容量 = 行数 × (数据位 + Tag + 有效位 + 脏位)

## 例题二

![](../../images/Pasted%20image%2020260919201722.png)

**考什么**：写回策略的脏位对 Cache 总容量的影响
**常见错因**
- 忘记写回策略需要 1 位脏位
- 把脏位算进数据位
- 有效位/脏位按字节算，而不是按行算

**解题模板**
1. 先按直接映射算 Tag/Index/Offset
2. 写回策略：每行加 1 位脏位
3. 每行开销 = Tag + 有效位 1 + 脏位 1
4. 总容量 = 行数 × (数据位 + 开销位)

**考什么**：直接映射的行号计算、Tag 比较、命中判断
**常见错因**
- 用主存地址直接比较，而不是用 Tag
- 忘记有效位
- 行号算错，导致比较了错误的行

**解题模板**
1. 由地址取 Index → 定位行
2. 取 Tag → 与该行 Tag 比较
3. 有效位 = 1 且 Tag 相等 → 命中
4. 否则缺失，按块调入并更新 Tag/有效位

## 例题四

![](../../images/Pasted%20image%2020260919202333.png)

**考什么**：直接映射的冲突缺失与替换
**常见错因**
- 认为直接映射可以任意选择替换行
- 忽略多个主存块映射到同一行
- 把“冲突”当成“容量不足”

**解题模板**
1. 算每个主存块的行号
2. 行号相同的块互相冲突
3. 直接映射只能替换该固定行
4. 冲突缺失多，是直接映射的主要缺点

**考什么**：数组访问顺序与空间局部性对命中率的影响
**常见错因**
- 只看数组大小，不看访问顺序
- 认为按列访问也一定能命中
- 忽略块大小与行大小的关系

**解题模板**
1. 确定数组元素大小、块大小、每块能放几个元素
2. 按行访问：连续元素在同一块，空间局部性好
3. 按列访问：跨行跳跃，块利用率低，冲突/缺失多
4. 比较两种访问的命中率与总访问时间
