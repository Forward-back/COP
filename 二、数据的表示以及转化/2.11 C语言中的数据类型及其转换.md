## 一、数据类型

### 1.1 类型

![](../images/Pasted%20image%2020260828134136.png)

**注**：寄存器中的操作数本身不存其是何种操作类型，对该数进行何种操作，取决于指令

**C 语言常见类型**
- `char` / `unsigned char`：8 位
- `short` / `unsigned short`：通常 16 位
- `int` / `unsigned int`：通常 32 位
- `float`：32 位 IEEE 754
- `double`：64 位 IEEE 754

**易错**
- C 标准只规定最小范围，具体位数由实现决定；408 按常见 32 位模型
- `char` 是否有符号由实现决定；408 通常按有符号 `char`
- 寄存器不保存“类型”，类型只决定指令如何解释位串

### 1.2 整型的取值范围

![](../images/Pasted%20image%2020260828134405.png)

| 类型 | 位数 | 范围 |
| --- | ---: | --- |
| `char` | 8 | $-128\sim127$ |
| `unsigned char` | 8 | $0\sim255$ |
| `short` | 16 | $-32768\sim32767$ |
| `unsigned short` | 16 | $0\sim65535$ |
| `int` | 32 | $-2^{31}\sim2^{31}-1$ |
| `unsigned int` | 32 | $0\sim2^{32}-1$ |

**注**：C 语言不自动检测溢出，参考 [[2.11A C语言不检测数据溢出的特性]]

## 二、类型转换

### 2.1 整型之间的转换

#### 2.1.1 相同字长之间的转换

以 `char` 与 `unsigned char` 举例

![](../images/Pasted%20image%2020260828135017.png)

分三种情况

1. 重叠区域的转换：`char` 转 `unsigned char`

![](../images/Pasted%20image%2020260828135113.png)

`unsigned char` 转 `char`

![](../images/Pasted%20image%2020260828135201.png)

**注**：重叠区域为 0 到 127 时，最高位为 0；无论把最高位当符号位还是数值位，都不影响真值，所以重叠区域的转换不改变真值

2. 独属 `char` 区域：`char` 转 `unsigned char`

![](../images/Pasted%20image%2020260828135721.png)

**注**：有符号转无符号，将最高位视为数值位；独属 `char` 区域的数均为负数，符号位为 1，视为数值位后贡献 256（8 位）

3. 独属 `unsigned char` 区域：`unsigned char` 转 `char`

![](../images/Pasted%20image%2020260828135951.png)

**注**：无符号转有符号，将最高位视为符号位；独属 `unsigned char` 区域的数最高位均为 1，视为符号位后相当于减去 256

**同字长转换公式**

$$\text{位串}_{\text{目标}}=\text{位串}_{\text{源}}\bmod 2^N$$

- 先按模 $2^N$ 截取位串，再按目标类型解释
- 8 位时，-1 的位串 `1111 1111` 按无符号解释为 255，200 的位串按有符号解释为 -56

#### 2.1.2 小字长转大字长

![](../images/Pasted%20image%2020260828140312.png)

![](../images/Pasted%20image%2020260828140429.png)

**注**：小字长转大字长的核心在于扩展
- 原数据为无符号：零扩展，高位补 0，**真值不变**
- 原数据为有符号：符号扩展，高位补符号位，**真值不变**

**重要纠错**
- 原笔记称“有符号负数符号扩展会改变真值”，这是错误的
- 符号扩展对正数和负数都保持真值不变；零扩展才会把负数解释成正数
- 例：`char -1`（`1111 1111`）→ `short -1`（`1111 1111 1111 1111`），真值仍是 -1
- 若把 `1111 1111` 零扩展成 `0000 0000 1111 1111`，真值变成 255，这才是改变真值

**判断口诀**
- 源类型无符号 → 零扩展
- 源类型有符号 → 符号扩展
- 目标类型不影响扩展方式，源类型才决定

#### 2.1.3 大字长转小字长

![](../images/Pasted%20image%2020260828140853.png)

**规则**
- 直接截断高位，保留低 $N$ 位
- 真值可能改变
- 有符号/无符号都按位截断，再按目标类型解释

**例**：32 位 `0x0000 01FF` 转 `char`，保留低 8 位 `0xFF`，按有符号 char 解释为 -1

#### 2.1.4 整型之间转换的总结

![](../images/Pasted%20image%2020260828140940.png)

| 转换 | 扩展/截断 | 真值 |
| --- | --- | --- |
| 同字长有符号 ↔ 无符号 | 按位重新解释 | 可能改变 |
| 短 → 长，源无符号 | 零扩展 | 不变 |
| 短 → 长，源有符号 | 符号扩展 | 不变 |
| 长 → 短 | 截断低位 | 可能改变 |

**易错**
- 扩展方式由“源类型”决定，不是目标类型
- 同字长转换不改变位串，只改变解释
- 长转短不是“四舍五入”，是截断
- 有符号溢出在 C 中是未定义行为；无符号是模回绕

### 2.2 int、double、float之间的转换

![](../images/Pasted%20image%2020260828141037.png)

#### 2.2.1 float转double

![](../images/Pasted%20image%2020260828141127.png)

- float 的尾数 23 位，double 尾数 52 位
- float → double 通常精确，不会丢失已有精度
- 阶码范围扩大，不会溢出

#### 2.2.2 double转float

![](../images/Pasted%20image%2020260828141201.png)

- 尾数从 52 位截到 23 位，可能丢失精度
- 阶码范围变小，可能上溢/下溢
- 需要舍入

#### 2.2.3 float/double 转 int

![](../images/Pasted%20image%2020260828141242.png)

- 向 0 截断，不是四舍五入
- 超出 int 范围时，C 标准是未定义行为
- 负数截断向 0，例如 -3.7 → -3

#### 2.2.4 int 转float

![](../images/Pasted%20image%2020260828141312.png)

- float 有效精度 24 位
- 32 位 int 超过 $2^{24}$ 时可能丢失低位
- 可能发生舍入

#### 2.2.5 int转double

![](../images/Pasted%20image%2020260828141354.png)

- double 有效精度 53 位
- 32 位 int 可以精确表示
- 64 位 int 超过 $2^{53}$ 时可能丢失精度

#### 2.2.6 总结

![](../images/Pasted%20image%2020260828141436.png)

| 转换 | 是否精确 | 风险 |
| --- | --- | --- |
| float → double | 通常精确 | 无 |
| double → float | 可能丢失精度 | 上溢/下溢/舍入 |
| float/double → int | 截断 | 超范围 UB |
| int → float | 超过 $2^{24}$ 可能丢失 | 舍入 |
| int → double | 32 位精确 | 64 位可能丢失 |

**易错**
- 浮点转整数是截断，不是四舍五入
- 整数转浮点可能丢失精度，不是“整数一定精确”
- double → float 可能溢出成 ∞
- C 语言不检测这些转换的范围，结果由实现/标准决定
