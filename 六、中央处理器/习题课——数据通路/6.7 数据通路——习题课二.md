# 6.7 数据通路——习题课二

**考纲定位**：计算机组成原理 · 第 6 章 中央处理器（6.7）｜重要度 ★★★★｜常见考法：大题（单总线数据通路、可见寄存器、控制信号位数、连线补全）

**一句话核心**：单总线题的通用套路是“先判可见性 → 再算控制字段 → 再画数据流 → 最后查单总线分时”

## 例题一

![](../../images/Pasted%20image%2020261009190647.png)

**本例考什么**

- 2015 题 43：16 位机、单总线、存储器与 I/O 统一编址
- 程序员可见寄存器、临时寄存器存在的理由
- ALUop/SRop 控制信号位数、SRout 的作用
- 补齐数据通路中缺失的控制信号连线

**常见错因**

1. 把临时寄存器（Y/Z/DR）当成程序员可见
2. 控制信号位数忘记包含“不发命令”的编码
3. 单总线同一拍安排两组传送，导致冲突
4. SRout 的作用写成“输出数据”，忽略它是三态门/输出使能
5. MUX 的“0”输入当成接地，实际是常数 0/清零

**解题模板**

1. 先列可见/不可见寄存器：PC、PSW、通用寄存器可见；MAR、MDR、IR、临时寄存器不可见
2. 控制字段位数：先数互斥组，再对每组取 ⌈log2(n+1)⌉
3. 每个部件问三个问题：输入从哪来、输出到哪去、何时有效
4. 补连线时，先找“有输入无来源/有输出无去向”的部件
5. 最后用单总线规则检查：同一拍只能有一组数据在总线上

**程序员可见性一览表**

| 分类 | 部件 | 说明 |
|---|---|---|
| 可见 | 通用寄存器（AX、R0~R31 等） | 指令直接读写 |
| 可见 | 程序计数器 PC | 存下条指令地址，跳转指令可修改 |
| 可见 | 程序状态字 PSW | ZF/SF/OF/CF，决定条件跳转 |
| 可见 | 堆栈指针 SP | 指向栈顶，配合 PUSH/POP/CALL/RET |
| 可见 | 基址/变址寄存器（BX/BP/SI/DI） | 实现基址、变址寻址 |

| 不可见 | MDR | 暂存与主存交换的数据 |
| 不可见 | IR | 存当前指令，取指时自动装入，无法访问 |
| 不可见 | Cache | 对应用程序员透明 |
| 不可见 | 微指令寄存器、流水线寄存器 | 控制器/微架构内部实现 |

**本例总结**

- 可见性判断标准：指令能否直接读写；不是“是不是寄存器”
- 临时寄存器的存在理由：单总线同一拍不能同时保存多个中间结果
- SRout 是输出使能/三态门控制，不是数据本身
- MUX 的 0 输入用于清零/选择常数 0，不是接地

## 例题二

![](../../images/Pasted%20image%2020261009191647.png)

**本例考什么**

- 与例题一类似的单总线数据通路，但寄存器/控制信号更复杂
- 要求分析指令执行流程、控制信号、最少节拍

**常见错因**

- 忘记取指阶段；直接从执行阶段开始
- 同一拍安排多次访存/多组总线传送
- 控制信号与动作不对应，或漏写使能信号
- 临时寄存器使用不当，导致数据被覆盖

**解题模板**

1. 先写取指阶段固定流程
2. 按指令类型拆执行阶段：取数 → 运算 → 写回/写存
3. 需要保存中间结果时用临时寄存器，不要在同一拍既写又读同一寄存器
4. 对照控制信号表逐拍填写
5. 最后检查 PC 更新、寄存器写回、存储器读写冲突

**变式提醒**

- 若改为双总线，ALU 两个操作数可同拍送出，节拍数减少
- 若增加间址周期，先取有效地址，再取操作数
- 若控制信号有效电平改变，所有写使能/读使能要同步调整
