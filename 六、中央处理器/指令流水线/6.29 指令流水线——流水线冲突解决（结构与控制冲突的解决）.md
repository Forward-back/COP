# 6.29 指令流水线——流水线冲突解决（结构与控制冲突的解决）

**考纲定位**：计算机组成原理 · 第 6 章 中央处理器（6.29）｜重要度 ★★★★｜常见考法：选择题（结构冲突、控制冲突、分支预测、延迟槽、冲刷）

**一句话核心**：结构冲突争资源，控制冲突争“下一条取哪”；前者靠资源重复/分时，后者靠预测/延迟/冲刷

## 一、流水线冲突的定义

![](../../images/Pasted%20image%2020261014171133.png)

**本图定位**：三类冲突的总览——结构、数据、控制

**考点/易错**

- 冲突（冒险）= 指令间依赖导致下一条指令不能在预期时钟进入流水线
- 结构冲突：争用同一部件/资源
- 数据冲突：后一条要用前一条尚未产生的结果（RAW）
- 控制冲突：分支/跳转导致后续取指可能作废
- 易错：三类冲突的成因不同，解决方法也不同，不要混

**补充**

- 408 常问“哪类冲突由分支引起”：控制冲突；“哪类冲突由指令与数据共用存储器引起”：结构冲突
- 数据冲突的详细判断见 6.30-6.32

## 二、结构冲突的解决

![](../../images/Pasted%20image%2020261014171212.png)

**本图定位**：结构冲突的典型场景与硬件解法

**考点/易错**

- 典型场景：取指与访存同时需要存储器；ALU 与地址计算同时需要运算器
- 解决：资源重复（指令 Cache 与数据 Cache 分离、增加加法器/端口）、资源分时、插入气泡
- 现代 CPU 的 L1 Cache 通常采用哈佛结构（指令/数据分离），就是为了消除取指与访存的结构冲突
- 易错：结构冲突不是数据相关；它是“资源不够”，不是“数据没算好”

**补充**

- 408 常问“指令 Cache 与数据 Cache 分离解决什么冲突”：结构冲突
- 资源重复会增加成本；资源分时会降低并行度

**本图定位**：分支/跳转让流水线“取错指令”的问题与解法

**考点/易错**

- 分支结果确定得越晚，流水线浪费越大；把分支判断提前到 ID 段可减少损失
- 解决：分支预测（静态/动态）、延迟槽、提前判断、预测错误时冲刷流水线
- 静态预测：总预测 taken/not taken 或按方向预测；动态预测：根据历史/计数器预测
- 预测错误要清除错误取入的指令（flush），并恢复正确 PC
- 延迟槽：在分支指令后安排一条无论分支是否成立都执行的指令
- 易错：分支预测不是“消除分支”；预测错误仍有代价
- 易错：控制冲突不是数据冲突；判断依据是“是否改变 PC/取指方向”

**补充**

- 408 常问“哪种方法对流水线性能影响最小/最大”：预测准确率越高，损失越小；延迟槽需要编译器配合
- 现代 CPU 用 BTB、方向预测器、返回地址栈等，但 408 只需掌握静态/动态预测与冲刷

## 四、易错辨析

- 结构冲突 = 资源争用；控制冲突 = 取指方向不确定；数据冲突 = 数据未就绪
- 指令/数据 Cache 分离解决结构冲突，不是数据冲突
- 分支预测解决控制冲突，不是数据冲突
- 延迟槽不是“延迟分支”，而是分支后固定执行的一条指令
- 预测错误必须冲刷；冲刷会浪费已取入的指令
