# 8.6 中断驱动方式概述

**考纲定位**：计算机组成原理 · 第 8 章 I/O 系统（8.6）｜重要度 ★★★｜常见考法：选择题（中断驱动 vs 程序查询、适用边界）

**一句话核心**：设备就绪后主动发中断，CPU 不必轮询；用中断开销换 CPU 与设备并行

![](../../../images/Pasted%20image%2020261103112725.png)

## 一、基本流程

1. CPU 向 I/O 设备发启动命令，当前进程阻塞，CPU 调度其他进程
2. 设备自主准备数据，此期间 CPU 执行其他任务
3. 设备准备就绪，向 CPU 发出中断请求
4. CPU 响应中断，执行中断服务程序，完成数据传送
5. 中断返回，CPU 回到被中断的进程或继续调度

- 与程序查询最大的区别：设备主动“敲门”，CPU 不需要反复读 DSR
- 数据传送本身仍由 CPU 执行中断服务程序完成，这一点与 DMA 不同

## 二、与程序查询的对比

| 维度 | 程序查询（轮询） | 中断驱动 |
|---|---|---|
| 触发方式 | CPU 主动查询设备状态 | 设备就绪后主动请求中断 |
| CPU 等待期间 | 忙等待或定时轮询 | 可执行其他任务 |
| 实时性 | 取决于轮询间隔 | 设备就绪立即通知，实时性更好 |
| 主要开销 | 轮询本身的时间 | 中断响应、上下文切换、ISR 开销 |
| 适用场景 | 简单系统、单任务、超高速设备 | 慢速/中速设备、多任务系统 |

![](../../../images/Pasted%20image%2020261103112753.png)

## 三、开销与适用边界

- 中断驱动消除了 CPU 的轮询开销，但仍有额外开销
  - 进程调度的两次上下文切换时间
  - 中断服务程序自身的执行开销
- 提高 I/O 效率的前提：上述额外开销 < 设备准备数据的时间
- 因此中断驱动适合慢速设备
- 对极高速设备，设备准备数据的时间极短，中断开销可能超过收益，反而不如程序查询的独占式查询策略
- 典型例外：NVMe SSD 在处理同步 I/O 时也会采用轮询方式

## 四、易错点

- 中断驱动不是“没有开销”，而是把“轮询开销”换成了“中断/上下文切换开销”
- 中断驱动不是 DMA：数据传送仍由 CPU 执行 ISR 完成
- 中断驱动不是对所有设备都更快：极高速设备可能反而不如独占式查询
- 中断驱动的前提是设备具备中断请求功能；没有中断功能的设备只能轮询
