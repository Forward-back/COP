# 8.8 中断优先级和中断屏蔽

**考纲定位**：计算机组成原理 · 第 8 章 I/O 系统（8.8）｜重要度 ★★★★｜常见考法：选择题（响应优先级 vs 处理优先级、屏蔽字、CPU 运行轨迹），偶作轨迹分析

**一句话核心**：响应优先级决定“同时到达谁先响应”，处理优先级决定“执行中谁能打断谁”；屏蔽字动态改写处理优先级

## 一、中断优先级

![](../../../images/Pasted%20image%2020261103113619.png)

- 中断优先级：CPU 响应并处理中断请求的先后次序
- 多个中断源同时向 CPU 发出中断请求时，CPU 先响应哪一个，取决于中断优先级
- 优先级高的先响应，优先级低的后响应
- 在多重中断（嵌套中断）中，高优先级中断请求可以中断 CPU 正在执行的低优先级中断服务程序（ISR）
- 中断优先级包含两个层面的含义：响应优先级和处理优先级

## 二、响应优先级 vs 处理优先级

![](../../../images/Pasted%20image%2020261103113733.png)

| 维度 | 响应优先级 | 处理优先级 |
|---|---|---|
| 定义 | CPU 对同时刻多个中断源请求的响应次序 | 多重中断中 CPU 实际处理中断的次序，即“谁能打断谁” |
| 决定方式 | 硬件设计时确定，一般不可改变 | 可通过中断屏蔽技术动态调整 |
| 划分依据 | 中断事件的重要性与紧迫性 | 中断屏蔽字 |
| 与另一者的关系 | 不使用屏蔽技术时，处理优先级与响应优先级相同 | 使用屏蔽技术后，两者可以不同 |

**响应优先级的一般划分**

1. 不可屏蔽中断 > 内部异常 > 可屏蔽中断
2. 内部异常中：终止（Abort）最高，其次是故障（Fault）和自陷（Trap）
3. DMA 中断 > I/O 设备传送中断
4. I/O 设备传送中断中：高速设备 > 低速设备，输入设备 > 输出设备，实时控制设备 > 普通设备

**处理优先级**

- 多重中断中实际的处理次序
- 可以利用中断屏蔽技术动态调整，使低优先级的中断也能打断高优先级的中断服务程序
- 现代计算机中普遍采用中断屏蔽技术

## 三、中断屏蔽

![](../../../images/Pasted%20image%2020261103113907.png)

- 中断控制器中包含中断屏蔽寄存器（Interrupt Mask Register，IMR）
- IMR 中的每一位对应一个设备中断源
- 为 1 表示屏蔽对应设备发送的中断请求信号
- 为 0 表示允许对应设备发送中断请求信号
- IMR 的值称为中断屏蔽字；通过给各设备配置屏蔽字，可以动态改变处理优先级的次序

**注意**

- 中断屏蔽仅对 CPU 运行中断服务程序（ISR）时的处理优先级（嵌套中断）起作用，不会影响 CPU 运行主程序时的中断响应优先级
- 若在 CPU 运行 ISR 时同时到达多个未屏蔽中断请求，处理优先级只能按响应优先级进行处理
- IMR 的值仅在执行中断服务程序（ISR）时才能被更新
- 屏蔽字由 ISR 用特权指令写入 IMR，是软件行为；不要与中断隐指令的“关中断、保存断点、中断识别”混为一谈

## 四、典型示例

![](../../../images/Pasted%20image%2020261103114222.png)

**示例 1：处理优先级与响应优先级一致**

- 响应优先级：A > B > C
- 屏蔽字（A、B、C 三位）：A = 111，B = 011，C = 001
- CPU 轨迹：主程序 → ISR_A → ISR_B → ISR_C
- 处理优先级：A > B > C，与响应优先级一致
- 解释：A 屏蔽所有中断，执行期间没人能打断；A 完成后 B 执行，B 屏蔽 B、C，只允许 A（已结束），所以 B 完成后才轮到 C

**示例 2：处理优先级与响应优先级相反**

- 响应优先级：A > B > C
- 屏蔽字：A = 100，B = 110，C = 111
- CPU 轨迹：主程序 → ISR_A → ISR_C → ISR_B → 回到 C → 回到 A
- 处理优先级：C > B > A，与响应优先级相反
- 解释：
  - A 的屏蔽字 100 只屏蔽自己，允许 B、C；B 的响应优先级高于 C，所以 B 打断 A
  - B 的屏蔽字 110 屏蔽 A、B，允许 C；C 打断 B
  - C 的屏蔽字 111 屏蔽所有，C 安心执行完；然后依次返回 B、A

**结论**：响应优先级只决定“同时到达谁先被响应”；进入 ISR 后，谁能打断谁由屏蔽字（处理优先级）决定

## 五、用 DFS/回溯理解中断嵌套

表面上看，中断嵌套像软件的深度优先搜索（DFS）和回溯，但实际上，这种嵌套和回溯由硬件（中断控制器、寄存器、堆栈）配合少量指令实现。把整个过程拆成三个核心机制：

### 5.1 机制一：IRR 锁存请求

- 当 A、B、C 同时产生中断请求时，它们各自向中断控制器发送电信号
- 中断请求寄存器（IRR）像位图一样锁存请求，对应位置 1
- 即使 CPU 正在执行主程序，IRR 也会一直锁存这些请求，保证请求不丢失
- 这是 DFS 中“把所有相邻节点压入栈”的硬件基础

### 5.2 机制二：IMR 与优先级仲裁

- 中断屏蔽寄存器（IMR）就是图中表格的内容；1 表示屏蔽，0 表示开放
- 优先级仲裁器决定当前应该响应谁
- 在示例 2 的设定中：响应优先级 A > B > C；屏蔽字 A=100、B=110、C=111

具体过程（DFS 的深入过程）：

1. CPU 最初执行主程序，IMR 可能是全 0；A、B、C 同时请求；仲裁器按响应优先级先响应 A
2. 进入 A 的 ISR 后，软件把 A 的屏蔽字 100 写入 IMR：屏蔽自己，但不屏蔽 B、C
3. B、C 的请求仍在 IRR 中；A 的屏蔽字允许 B、C 打断，硬件发现 B 的优先级高于 C，于是暂停 A，转去执行 B
4. 进入 B 的 ISR 后，软件把 B 的屏蔽字 110 写入 IMR：屏蔽 A、B，但不屏蔽 C
5. C 立刻打断 B，CPU 转去执行 C
6. 进入 C 的 ISR 后，软件把 C 的屏蔽字 111 写入 IMR：屏蔽 A、B、C，没有设备能打断 C
7. C 执行完，通过中断返回逐层回溯到 B、A、主程序

### 5.3 机制三：堆栈与中断返回

- CPU 内部有栈指针 SP，内存中开辟系统堆栈
- 主程序被打断时，硬件自动把主程序的断点（PC）和 PSW 压入堆栈
- A 被打断时，硬件压入 A 的断点与 PSW；B 被打断时，压入 B 的断点与 PSW
- 进入 ISR 后，软件再保护通用寄存器等现场
- C 执行完执行 IRET，硬件弹栈恢复 B 的断点/PSW 与屏蔽字，回到 B
- B 执行完再弹栈回 A；A 执行完弹栈回主程序
- 这就是 DFS 的“回溯”

**类比局限**：DFS 是纯软件递归；中断嵌套由硬件保存断点/PSW、软件保存通用寄存器与屏蔽字共同完成，压栈内容和时机与普通函数调用不同

## 六、易错点

- 响应优先级是硬件固定的；处理优先级可以通过屏蔽字动态改变
- 屏蔽字 1 = 屏蔽，0 = 允许；不要记反
- 屏蔽字只影响 ISR 执行中的处理优先级，不影响主程序运行时的响应优先级
- 屏蔽字由 ISR 软件写入，不是硬件自动写入
- 同时到达多个未屏蔽请求时，处理优先级只能按响应优先级
- 低优先级中断可以打断高优先级中断，只要屏蔽字允许
- 不使用屏蔽技术时，处理优先级与响应优先级相同
- 中断屏蔽与“关中断（IF=0）”不是一回事：前者按位屏蔽某个中断源，后者屏蔽所有可屏蔽中断

## 七、考法透视

**常见题型**

- 给响应优先级和屏蔽字，画 CPU 运行轨迹或判断处理次序
- 给 CPU 运行轨迹，反推各设备的屏蔽字
- 判断某中断能否打断当前 ISR
- 区分响应优先级与处理优先级
- 结合 [[8.11 多重中断的处理流程]] 判断开关中断与 EOI 的位置

**常见设错点**

1. 认为响应优先级可以靠屏蔽字改变
2. 认为处理优先级一定等于响应优先级
3. 认为屏蔽字 0 表示屏蔽
4. 认为屏蔽字由硬件自动设置
5. 认为低优先级永远不能打断高优先级
6. 把“中断屏蔽”与“关中断”混为一谈

## 九、费曼自测

1. 响应优先级和处理优先级的区别是什么
   → 响应优先级决定同时到达谁先响应，硬件固定；处理优先级决定执行中谁能打断谁，可由屏蔽字动态调整

2. 屏蔽字中 1 和 0 分别表示什么
   → 1 表示屏蔽，0 表示允许

3. 为什么低优先级中断能打断高优先级中断
   → 因为屏蔽字允许；处理优先级由屏蔽字决定，不必等于响应优先级

4. 屏蔽字由谁写入，什么时候生效
   → 由 ISR 用特权指令写入 IMR；仅在执行 ISR 时影响处理优先级

5. 不使用屏蔽技术时，处理优先级和响应优先级是什么关系
   → 相同
