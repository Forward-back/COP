# 8.4 I/O 控制方式概述

**考纲定位**：计算机组成原理 · 第 8 章 I/O 系统（8.4）｜重要度 ★★★｜常见考法：选择题（五种控制方式的特点、适用场景、CPU 参与程度）

**一句话核心**：I/O 控制方式按 CPU 参与程度从高到低依次为：程序查询 → 中断驱动 → DMA → 通道 → I/O 处理机

![](../../images/Pasted%20image%2020261102204947.png)

## 一、五种控制方式

| 方式 | 核心思想 | CPU 参与程度 | 数据单位 | 适用场景 |
|---|---|---|---|---|
| 程序直接控制（查询） | CPU 轮询状态寄存器 DSR，设备就绪后再传送 | 完全或部分被占用 | 字/字节 | 低速设备、简单系统 |
| 中断驱动 | 设备就绪后主动向 CPU 发中断，CPU 在等待期间执行其他任务 | 响应中断时参与 | 字/字节 | 低速/中速设备、多任务系统 |
| DMA | DMAC 接管总线，设备与主存之间直接成块传送 | 仅初始化与结束阶段 | 数据块 | 高速设备、大批量数据 |
| 通道 | 通道执行通道程序，独立管理一组 I/O 设备 | 只发启动命令 | 数据块/一组块 | 高速设备、大型系统 |
| I/O 处理机 | 拥有独立指令系统与存储器，处理复杂 I/O 任务 | 几乎不参与 | 数据块/程序 | 大型机、复杂 I/O |

- 程序查询与中断驱动主要由软件实现，数据传送仍由 CPU 执行程序完成
- DMA、通道、I/O 处理机主要由硬件实现，CPU 逐步从数据搬运中卸载
- 从程序查询到 I/O 处理机，本质是不断把“等待”和“搬运”从 CPU 交给专门的硬件

## 二、演进逻辑

- 程序查询：CPU 主动等设备，设备没就绪就反复查，CPU 空转
- 中断驱动：设备主动通知 CPU，消除轮询，但每传送一个字/字节仍要 CPU 介入
- DMA：数据搬运交给 DMAC，CPU 只做初始化与善后
- 通道：DMAC 升级为能执行通道程序的处理器，可管理一组设备
- I/O 处理机：通道进一步独立，拥有自己的指令系统与存储器，处理更复杂的 I/O 任务

## 三、易错点

- DMA 不是“全程无 CPU”：预处理（设参数、启动设备）和结束（中断善后）都需要 CPU
- 通道 ≠ DMA：通道能执行通道程序、管理多台设备；DMA 通常一次管理一个设备的数据块
- 中断驱动 ≠ DMA：中断方式的数据传送仍由 CPU 执行程序完成，DMA 由硬件直接搬运
- 程序查询不一定只适合慢速设备：超高速设备准备数据极快，轮询等待很短，也可以采用
- “主要由软件实现/硬件实现”是相对说法，DMA 的初始化与结束仍有软件参与
